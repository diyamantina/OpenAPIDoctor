Why a Swift-specific doctor?

General linters check style. OpenAPIDoctor predicts whether your spec will actually compile through Apple's generator — and fixes it.

🎯

Same parser as the generator

Built on OpenAPIKit — the library swift-openapi-generator uses. If the doctor says it's clean, codegen won't choke.

🔧

Auto-repair, not just complain

Strips stray vendor-extension keys, drops nullable: true on 3.1, injects missing servers, and synthesizes missing operationIds.

🔒

Your spec stays yours

Compiles to WebAssembly, so the web tool runs entirely client-side. Private API specs never touch a server.

🗂️

Multi-file & corpus aware

Resolves external $refs across folders and validates entire directories of specs in one pass.

⚙️

CLI + library + CI

Use it from Swift, from the shell with openapi-doctor, or as a pull-request gate in CI.

🍎

macOS, Linux & Wasm

Pure-Swift YAML stack — no libYaml C dependency — so it builds everywhere Swift runs.

Use it in 30 seconds

The core library and CLI are free and open source (MIT).

# Swift Package Manager
.package(url: "https://github.com/mihaelamj/OpenAPIDoctor", from: "1.0.0")

# Or the CLI
swift build -c release
cp .build/release/openapi-doctor /usr/local/bin/

openapi-doctor --fix openapi.yaml
